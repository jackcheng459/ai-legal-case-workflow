## 阶段3：起诉阶段材料制作

> **适用条件**：`role=plaintiff` 时执行。被告方代理跳过此阶段，从阶段4开始。

**目标**：准备向法院提交的全部立案法律文书，完成起诉材料包。

**输入**：阶段1案件概要报告 + 阶段2主体核查报告

**子代理架构**（可并行）：

```
主代理（协调者）
├── complaint-drafter      → 民事起诉状.md
├── evidence-cataloger     → 本诉证据目录.md
├── preservation-applicant  → 财产保全申请书.md（如需）
├── property-investigator   → 财产调查申请书.md（如需）
└── legal-verifier          → 起诉阶段法源核实报告.md
```

**操作步骤**：

1. **确定诉讼请求**
   - 基于阶段1的案件分析，设计诉讼请求（本金+利息+违约金+律师费+诉讼费承担）
   - 利息计算到实际清偿之日，列明计算公式
   - 确认诉讼标的额并计算诉讼费

2. **确定管辖法院**
   - 审查协议管辖条款效力
   - 无协议管辖时按被告住所地或合同履行地确定
   - 评估管辖权异议风险

3. **起草核心文书**（是否启用子代理按阶段5步骤1的四项判断执行，`parallel_enabled=true` 只表示具备资格，不表示直接启动）
   - `complaint-drafter`：起草起诉状（事实+理由+请求），事实部分与证据目录严格对应
   - `evidence-cataloger`：编制证据目录，按证明目的分组，每项列明编号、名称、来源、形式、证明目的、证明力评级
   - `legal-verifier`：通过当前可用的权威来源核实起诉状引用的全部法条

4. **保全与调查申请**（根据阶段2评估结果）
   - 如需保全：`preservation-applicant` 起草保全申请书，确定担保方式（财产担保/保险公司保函/担保公司担保），附财产线索
   - 如需调查：`property-investigator` 起草财产调查申请书，明确调查范围（银行账户、不动产、车辆、股权、应收账款等）

5. **编制立案材料清单**
   - 起诉状正本+副本（按被告人数+1）
   - 证据目录+证据材料（同上份数）
   - 当事人主体材料（营业执照/身份证复印件）
   - 授权委托书+律师执业证复印件
   - 送达地址确认书
   - 诉讼费缴费计算单

**输出模板**：详见 `references/templates.md` 中的"起诉材料包模板"

**关键经验**：
- 诉讼请求金额覆盖利息计算到实际清偿日，避免立案后变更请求
- 起诉状事实部分必须与证据目录逐项对应，防止"有事实无证据"
- 保全申请尽早提交，避免被告收到起诉状后转移财产
- 保全担保首选保险公司保函，成本最低（保费约为担保金额的0.3-0.8%）
- 证据目录按"合同关系成立→违约事实→损失计算→其他"分组，逻辑清晰
- 起诉状副本份数 = 被告人数 + 法院留存1份

**异常处理**：

| 异常场景 | 检测方式 | 回退策略 |
|----------|----------|----------|
| 管辖权异议风险高 | 协议管辖条款无效或被告在异地 | 评估移送管辖概率，必要时选择有利管辖法院 |
| 证据不足 | 关键事实无证据支撑 | 列出待补充证据清单，建议补充后再立案 |
| 保全担保困难 | 当事人无法提供现金担保 | 推荐保险公司保函，联系保险公司获取报价 |
| 诉讼费过高 | 标的额大导致诉讼费超出预算 | 评估分案起诉或降低请求金额的可行性 |

## 阶段4：反诉分析与应对策略

**目标**：系统分析对方反诉/答辩的请求权基础，识别薄弱环节，制定应对策略。

**输入**：阶段3起诉材料（原告方）或 收到起诉状（被告方） + 对方反诉/答辩材料

**场景分支**：

| 场景 | 条件 | 处理方式 |
|------|------|----------|
| 有反诉 | 对方提起反诉 | 完整执行本阶段全部步骤 |
| 仅答辩无反诉 | 对方仅提交答辩状 | 跳过反诉分析，执行答辩分析和庭审准备步骤 |
| 对方未提交答辩状 | 答辩期届满未收到答辩状 | 不等于对方不应诉。仍按对方可能到庭抗辩准备全套材料，同时排查是否存在送达瑕疵 |
| 对方经合法传唤未到庭 | 法院通知或庭审当日确认 | 核实送达是否合法，包括公告送达期间是否届满；缺席审理时强化举证充分性和法律论证，不得降低准备标准 |

**操作步骤**：

1. **读取对方材料**
   - 按顺序读取全部起诉与反诉/答辩材料（先本诉后反诉）
   - 标注对方新提交的证据（对比我方证据清单）

2. **逐项拆解反诉/答辩请求**
   - 请求事项 + 事实依据 + 法律依据
   - 区分"否认型答辩"（否认我方主张）和"主张型反诉"（独立请求）

3. **请求权基础构成要件分析**
   - 分析每项请求的请求权基础（识别法律规范构成要件）
   - 逐要件评估对方举证满足度
   - 标注对方举证不能的要件（攻击点）

4. **管辖权异议分析**
   - 对方是否提出管辖权异议
   - 评估异议理由是否成立
   - 准备管辖权异议答辩（如法院移送管辖）

5. **诉讼时效抗辩分析**
   - 对方是否提出诉讼时效抗辩
   - 我方时效中断/中止事由是否充分
   - 如时效届满，评估对方放弃时效抗辩的可能性

6. **识别对方证据薄弱环节**
   - 无明细损失主张
   - 缺乏因果关系证明
   - 举证不能
   - 证据形式瑕疵（复印件、无签字）

7. **识别我方不利证据**
   - "双刃剑"证据（如通话录音中不利表述）
   - 每项不利证据制定化解方案

8. **证据交换策略**
   - 评估是否在庭前证据交换中出示全部证据
   - 保留"杀手锏"证据到庭审出示的可能性
   - 评估对方可能补充的证据方向

9. **制定逐项应对策略**
   - 反驳思路 + 法律依据 + 证据运用方案
   - 区分"可全部否认""部分承认""需另行主张"

10. **评估调解空间**
    - 双方强弱态势分析
    - 预判调解可能性和条件
    - 调解底线建议

**输出模板**：详见 `references/templates.md` 中的"反诉分析报告模板"

**关键经验**：
- 双刃剑证据提前识别并准备化解方案
- 损失金额逐项核查：无明细、含无关费用、未扣残值是常见问题
- 区分行政认定与质量认定
- 关注举证时序：付款到期后才提质量问题影响抗辩可信度
- 管辖权异议是程序性武器，不要因急于实体辩论而忽略
- 诉讼时效抗辩即使不成立也要准备，对方可能不知道时效已中断

## 阶段5：应诉材料包制作（协作可选）

**目标**：通过多子代理并行协作，高效完成答辩/庭审准备全套材料。

**输入**：阶段4策略报告 + 全部案卷材料

**架构设计**：

```
主代理（协调者）
├── defense-drafter       → 答辩状/代理词.md
├── evidence-organizer    → 证据目录与质证意见.md
├── legal-researcher      → 法源核实报告.md
├── counter-analyst       → 对抗复核与抗辩策略报告.md
├── trial-questioner      → 庭审发问提纲.md
└── mediation-assessor    → 调解预研报告.md
```

**操作步骤**：

1. 依次判断四项：任务是否复杂到需要拆分、是否存在两个以上可独立执行的子任务、平台是否具备多代理能力、并行是否会突破既有数据和工具授权边界。四项全部满足才启动并行，任一不满足由主代理串行执行，角色分工不变。启动前告知资源消耗可能明显增加
2. 使用平台对应能力创建协作空间，并为每个子代理创建边界清楚的任务
3. 在平台支持的范围内并行启动全部子代理，记录实际启动状态
4. 各子代理独立读取材料、完成任务、提交产出
5. 主代理审核各子代理产出，提出具体修改意见
6. 整合为应诉材料包，编制总目录
7. 向所有子代理发送关闭请求，确认产出已保存后使用平台对应能力清理资源

**子代理详细职责**：

- **defense-drafter**：逐条回应反诉请求/答辩意见，每条附法律依据，经审核修改后定稿。区分"否认型答辩"和"主张型反诉"的回应方式
- **evidence-organizer**：按本诉/反诉分类编制证据目录，每项列明名称、来源、证明目的、证明力分析；同时准备对对方证据的质证意见（真实性/合法性/关联性）
- **legal-researcher**：通过当前可用的权威来源逐条验证法条效力，检索支持性判例，标注不利判例，准备管辖权异议和诉讼时效的法条支撑
- **counter-analyst**：站在对方角度审查材料，逐项质证对方证据，制定庭审对抗预案，识别对方可能的"杀手锏"证据
- **trial-questioner**：设计庭审发问提纲（向对方当事人/证人发问的问题清单），预测对方可能的发问及我方回应
- **mediation-assessor**：基于阶段4的调解空间评估，进一步细化调解方案（含底线方案、目标方案、开价方案），评估调解时机和策略

**输出模板**：详见 `references/templates.md` 中的"应诉材料包模板"

**关键经验**：
- 并行启动：只有任务复杂、存在两个以上独立子任务、平台支持且不突破既有数据和工具授权边界时才启用；否则保持同一角色分工，改为串行执行
- 审核闭环：主代理必须审核并提出具体修改意见
- 法源核实是底线：禁止凭记忆引用，必须通过当前可用的权威来源验证；核实通过的逐条标注 `【已核实：<来源名称>，YYYY-MM-DD】`，日期写实际核实日期，不得使用占位符
- 子代理完成后立即关闭，避免资源占用
- 发问提纲要具体到每个问题的预期答案和追问方向
- 调解预研在此阶段完成，不要等到庭审后才考虑调解
