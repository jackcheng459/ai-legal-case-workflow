# 民事二审 A0–A6 工作流

识别为 `procedure=second_instance` 时读取本文件。本模块处理中国民事判决上诉，以及《民事诉讼法》规定的三类通常可上诉裁定；它不是再审、执行或全部裁定救济手册。

## 通用边界与法律核验

### 处理范围

- 判决上诉：代理上诉人、被上诉人或同一案件中的双轨上诉应对。
- 裁定上诉：仅处理不予受理、管辖权异议、驳回起诉三类通常可上诉裁定。
- 不处理：刑事或行政上诉、再审、执行异议与复议、第三人撤销之诉、特别程序及其他专项救济。
- 涉外、港澳台、知识产权、海事海商、破产衍生诉讼只做识别和专项核验闸门；不得把普通二审规则直接作为专项结论。

### 法源基线

下列条号只作为工作流检索锚点，实际案件必须在执行时重新核验现行有效文本并标注核验日期：

| 事项 | 检索锚点 |
|---|---|
| 上诉期限、上诉状、递交路径、答辩和卷宗移送 | 《民事诉讼法》第171–174条 |
| 审理范围、审理方式、裁判结果、调解、撤回、终审和审限 | 《民事诉讼法》第175–183条 |
| 通常可上诉裁定 | 《民事诉讼法》第157条 |
| 小额诉讼一审终审 | 《民事诉讼法》第165条 |
| 无中国境内住所当事人的上诉和答辩期间 | 《民事诉讼法》第286条 |
| 多方上诉、审理范围、新请求、程序严重违法、撤回 | 《民事诉讼法司法解释》第315–340条相关规定 |
| 二审新证据举证期限 | 《最高人民法院关于民事诉讼证据的若干规定》第51条 |
| 上诉费用与预交 | 《诉讼费用交纳办法》第8、17、20、22、27、30、40条 |

维护时优先核对：[全国人大 2023 年修法决定](https://www.npc.gov.cn/npc/c2/c30834/202309/t20230901_431419.html)、[最高人民法院公报现行民事诉讼法文本](https://gongbao.court.gov.cn/Details/34dde9559bbdcdf7ef2dc0d716f5a8.html)、[最高人民法院民事诉讼法司法解释](https://www.court.gov.cn/zixun/xiangqing/353651.html)、[最高人民法院民事证据规定](https://www.court.gov.cn/zixun/xiangqing/212721.html)、[诉讼费用交纳办法](https://www.court.gov.cn/jianshe/xiangqing/5092.html)。这些链接不替代运行时的效力核验。

### 二审工作底座

所有阶段组共用以下对象：

1. `appeal_track`：每一份上诉独立编号，如 `AT-01-我方上诉`、`AT-02-对方上诉`。
2. `claim_id`：原审诉讼请求及二审请求逐项编号。
3. `finding_id`：原审事实认定、证据采信和裁判理由逐项编号。
4. `evidence_id`：沿用原审编号；二审新增证据单设前缀，不重排原审证据。
5. `issue_id`：将每个上诉争点连接到请求、认定、证据、法源和结果影响。

任何跨文书不一致都回到上述底座修正，不在单份文书中局部圆回。

## A0 入口、可上诉性、期限与费用

### 目标

先回答“能否按普通二审处理、现在必须做什么”，再讨论实体上诉理由。

### 步骤

1. 优先读取 `decision_path` 指向的原审裁判文书；未单列时从 `materials_path` 识别，并核对全部页面、裁判日期、文书类型、程序告知和签章。
2. 读取 `service_records` 中的送达证、电子送达回执、邮寄轨迹、签收记录或庭审当庭宣判记录；未单列时从材料目录识别，区分裁判日期与实际送达事实。
3. 判断是否一审裁判、是否一审终审、是否属于三类可上诉裁定。
4. 对每一当事人分别建立期限轨道：主体、文件类型、送达方式、送达日证据、法定期间、拟采取动作、当前状态和复核人。
5. 以提交凭证核验 `client_filed_appeal`，以法院送达或卷宗材料核验 `other_party_filed_appeal`；据此建立或更新 `appeal_tracks`，并核对上诉状是否书面提交、提交法院和移送状态。
6. 核对 `appeal_fee_status`、计费基础、预交通知、缴费截止日和凭证。财产案件按不服一审判决部分计算；多方分别上诉时分别核查预交。
7. 输出入口结论、立即行动清单和律师裁决点，通过 D0 后进入 A1。

受控三类裁定的上诉案件一般不交纳案件受理费，但仍须核对裁定类型、法院通知和现行费用规则，不自行把其他裁定扩展为免缴情形。

### 期限基线

| 场景 | 一般规则 | 工作流要求 |
|---|---|---|
| 境内当事人不服一审判决 | 送达之日起十五日内 | 必须以可核验送达事实为起点 |
| 境内当事人不服可上诉裁定 | 送达之日起十日内 | 先确认裁定类型在受控范围内 |
| 无中国境内住所当事人 | 判决或裁定上诉期间一般为三十日 | 标记专项要素，并重新核验条文、送达规则和国际协定 |
| 对方收到上诉状副本后的答辩 | 境内一般十五日；无境内住所一般三十日 | 没有答辩不影响审理，但应保留提交计划 |
| 上诉费 | 结合上诉时提交、法院通知和七日补交规则核验 | 只凭“已递交上诉状”不得认定程序安全 |

> 没有裁判文书或可核验送达记录时，`deadline_status=unverified`，不得写“仍在上诉期内”。对自然日、法定期间届满、节假日顺延和法院通知之间的关系，应以现行法及实际受理法院要求复核。

### D0 阻断条件

- 文书类型或审级无法确认。
- 普通上诉权不存在，却仍准备普通上诉状。
- 送达事实缺失，但输出确定截止日。
- 多个当事人或多个上诉轨道被合并计算。
- 缴费状态未知，却把上诉写成已经完成。

## A1 原审卷宗与裁判拆解

### 目标

把原审“请求、抗辩、争点、证据、认定、理由、主文”重建为可追溯结构，而不是只摘要判决书。

### 步骤

1. 建立原审材料清单：诉状、答辩、反诉、证据目录、质证、庭审笔录、代理意见、程序裁定和裁判文书。
2. 对照原审请求与主文，标记支持、驳回、遗漏、超出或表述差异。
3. 逐项拆解原审认定：引用段落、所依据证据、采信理由、反证或冲突材料、举证责任分配。
4. 逐项拆解法律适用：请求权基础、构成要件、解释方法、法条效力和裁判逻辑。
5. 识别程序节点：管辖、送达、回避、举证、鉴定、证人、庭审组成、辩论权和遗漏当事人。
6. 把当事人主张与法院认定分栏，禁止将未被采信的主张写成已认定事实。
7. 为可能进入 A2–A6 的关键事实建立登记表：`fact_id`、事实命题、`source_role`、`statement_actor`、原文与页码、事件时间、统计截止时间、核验状态、反向材料和下游文书。来源角色至少区分 `original_document`、`party_assertion`、`court_finding`、`court_recorded_undisputed`、`lawyer_observation`、`analysis_inference`、`lawyer_decision`。
8. 金额不得脱离时点单独复用。同一数值在不同阶段出现时，分别记录事件发生日、统计截止日、计算式和对应载体；无法确认时保留独立待核项。

### 核心产出

- 原审请求与主文对照表。
- 裁判认定和证据依据矩阵。
- 原审程序事件时间线。
- 未入卷、不可读、相互冲突和待核实材料清单。
- 关键事实与金额时点登记表。

## A2 上诉请求与裁判错误审计

### 目标

将“不同意原判”转化为能够影响裁判结果的具体审计链，并向律师提供可选择的策略，而不是替律师自动决定。

### 错误分类

| 类型 | 核查问题 | 结果连接 |
|---|---|---|
| 事实认定 | 认定是否缺乏证据、遗漏关键事实或误读证据 | 纠正后是否改变构成要件或金额 |
| 证据评价 | 真实性、关联性、合法性和证明力评价是否有误 | 是否足以动摇关键认定 |
| 法律适用 | 请求权基础、条文、效力、举证责任或解释是否有误 | 正确适用后主文如何变化 |
| 程序处理 | 是否存在剥夺辩论权、违法缺席、审判组织违法、遗漏请求或必要当事人等 | 应改判、调解、发回或另行处理的边界 |
| 裁判计算 | 本金、利息、违约金、期间、责任比例或费用计算是否错误 | 给出可复核的替代计算 |

### 步骤

1. 对每个 `appeal_track` 分别提取上诉请求、事实理由、请求变更范围和对应主文。
2. 建立 `请求 → 错误主张 → 原审段落 → 证据 → 法源 → 结果影响` 链。
3. 区分强理由、需补证理由、程序性理由和仅表达不满但缺乏结果影响的理由。
4. 对上诉人生成至少两个策略选项；对被上诉人同时生成“维持原判主线”和必要的备选防御。
5. 每个选项列明成立条件、潜在收益、主要风险、所需证据、程序动作和律师裁决点。
6. 不输出胜率百分比。可使用“证据支持较强/存在关键缺口/需专项核验”等可解释分级。

### 多方上诉

- 全部当事人和第三人均上诉时，先依据现行司法解释核验各方诉讼地位。
- 一方对另一方的不同上诉分别建立轨道，保持请求和期限独立。
- 共用事实底座，但上诉状、答辩状和证据引用必须标明轨道。
- 任一轨道变化时运行跨轨道一致性检查，防止本方上诉主张与对对方上诉的答辩自相矛盾。

## A3 证据增量、新请求与程序事项

### 新证据

1. 先把“二审新提交材料”作为中性事实描述，不直接等同于法律意义上的“新证据”或“不予采纳”。
2. 对每份材料记录来源、形成时间、取得时间、原审提交状态、原审是否质证、原审未提交原因、证明目的、与原审材料的同一性和范围差异、真实性核验方式。
3. 材料状态至少区分：`original_recorded`、`original_submitted_unverified`、`repeated_same_material`、`expanded_or_more_complete_copy`、`newly_formed`、`newly_obtained`、`unknown`。同一组文件可以包含不同状态，必须逐份判断。
4. 二审法院指定新证据举证期限时，以现行证据规定“不少于十日”的最低期间要求为核验锚点，并以法院实际通知和个案程序为准。
5. 评估逾期提交的理由、材料与案件基本事实的关系及现行法上的分层后果；不把“新找到”自动等同于“新证据”，也不把“原审已有同主题材料”自动等同于整组材料均不属于增量或均不应采纳。
6. 新证据导致增加的诉讼费用可能涉及过错承担，列为费用风险。

### 新请求与程序问题

- 对原审遗漏诉讼请求、遗漏必要当事人、二审新增独立请求或反诉分别处理，不混为普通上诉理由。
- 二审新增独立请求或反诉通常先核验调解及另行起诉规则；只有符合法定条件且当事人同意时，才讨论二审一并裁判。
- 严重程序违法必须连接到具体庭审或程序材料，不根据当事人感受直接下结论。
- 申请调查取证、鉴定、证人出庭或保全时，分别说明必要性、材料基础、期限和法院裁量边界。

### 缺口关闭计划

每项缺口至少包含：`gap_id`、影响的争点、缺失材料、获取路径、责任人、截止时间、失败替代方案和当前状态。无法关闭的缺口必须进入 A4 文书风险披露。

## A4 二审文书材料包

### 上诉人材料

- 民事上诉状或受控裁定上诉状。
- 上诉请求与裁判错误矩阵。
- 二审证据目录和新增证据说明。
- 法源核验报告、程序申请和费用凭证清单。

### 被上诉人材料

- 二审答辩状，逐项对应对方上诉请求和理由。
- 维持原判的事实、证据和法律链。
- 对原审瑕疵但裁判结果正确情形的备选论证。
- 对方新增证据的质证框架和本方程序申请。

### 文书一致性

- 用户或律师明确指定既有文书为后续基准时，记录 `authoritative_base_path`、版本或内容指纹和指定时间；先比较该文件与 AI 草稿的差异，再在该基准上增量修订并另存新版本。
- 请求必须可执行、边界明确，并与当事人授权一致。
- 原审裁判引文逐字核对页码，不能用模型概括替代原文。
- 同一事实、金额、日期和证据编号在上诉状、答辩状、证据目录和庭审提纲中保持一致；一致性不能用同一错误在多份文书中重复来证明，仍须回关键事实登记表和原始载体复核。
- 对尚未经权威来源核实的法律意见使用统一未核实标识。
- 对方尚未提交上诉状时，不生成假想答辩状；进入 `waiting_external`，可先建立答辩骨架。
- 关键事实或法源更正时建立 `correction_cascade`，全文搜索全部下游文件，列出已更新、保留但过期、仍待更新和无需更新的文件。只修当前文书不能通过 D4。

## A5 庭审、询问、调解与庭后补强

### A5/A6 阶段门禁

- 庭前准备、正在开庭或询问、当庭质证、庭审记录整理和裁判作出前的庭后补强均属于 A5。产出类型用 `artifact_type` 单独记录，不得因文件名含“庭后”“分析”或“质证”而改写 `phase_id`。
- 进入 A6 必须有可读取的 `second_instance_terminal_document_path`，或有能够回链法院通知、送达记录、法院系统页面等官方原始载体且 `verification_status: verified` 的 `terminal_event`。原审 `decision_path` 不能替代；律师记录、当事人口述、电话转述或普通即时通信信息不能满足门禁。
- 只有已核验官方事件而没有终局文书全文时，可以进入 A6 的 `procedure_status_only` 范围，但 `run_status` 保持 `waiting_external`，只记录程序状态、载体、送达或取得动作和期限，不得生成裁判理由、实体结果或权利义务影响分析。
- 庭审结束但尚无上述入口证据时固定为 `second_instance_stage: post_hearing`、`phase_id: A5`、`run_status: waiting_external`、`waiting_for: 二审终局文书或可核验官方事件`；不得生成 A6 文件。

### 审理方式预检

二审以开庭审理为原则。只有在阅卷、调查和询问后，没有提出新的事实、证据或理由，且法院认为不需要开庭时，才可能不开庭。三类受控裁定上诉属于现行《最高人民法院关于适用〈中华人民共和国民事诉讼法〉的解释》第三百三十一条明确列举的可以不开庭审理情形，应同步准备询问或书面审理材料。不得把“可以不开庭”写成“必然书面审理”，也不得提前承诺“必然开庭”。

### 庭前或询问准备

1. 将上诉请求限定的审理范围与法定例外分开列示。
2. 为每个争点准备：待证事实、证据、对方弱点、法源、发问、可能追问和底线回答。
3. 对二审新提交材料逐项核对原审提交状态、材料同一性、范围差异、真实性、关联性、合法性、证明目的和逾期理由；法律标签必须建立在现行法核验和上述事实分类之上。
4. 建立法官可能关注点，但不得据此预测结果。
5. 调解方案列明授权范围、财务测算、履行保障、违约后果和需客户另行确认事项。

### 庭中限时模式

只有用户明确处于实际庭审、法庭询问过程，或法院要求现场即时回应时，才启用 `hearing_context: live`。非现场的“尽快”“今天”“下班前”仍使用 `normal`。它是 A5 内的呈现与执行模式，不是新阶段，也不要求现场重做全案。根据 `time_budget_minutes` 和 `current_question` 按下列顺序输出：

1. 说明当前可用材料、记录来源、任务边界和不能确认的事项。
2. 先做与当前问题直接相关的必要分析，包括证明目的、真实性或证明力争议、与既有事实证据底座的矛盾、已核实法源和未决事项。
3. 在上述分析之后给出总结性结论。
4. 提炼可当庭使用的质证或答复要点。
5. 提出必要的程序请求、异议或保留意见。
6. 列明证据页码或其他定位，以及尚未核实、不得当庭确定表述的内容。
7. 需要完整法律意见时，保留至庭后在材料和法源补充核验后生成。

未提供 `time_budget_minutes` 时，如现场允许只追问一次；否则标记 `unknown` 并输出最小但完整的分析，不以固定行数压缩。不得先给结论再补分析，也不得为追求即时性把未核法源、律师记忆或不完整记录包装为确定事实。

### 庭审偏差、记录来源与庭后动作

- `artifact_type` 只使用 `hearing_live_response`、`hearing_delta_log`、`post_hearing_action_list`、`post_hearing_opinion`、`terminal_status_receipt`、`terminal_analysis_report` 或 `delivery_archive`，用于区分产出，不改变 `phase_id`。
- 仅在实际出现新证据、新陈述、争点变化、立场张力、法院要求、期限或调解条件变化时，维护一张 `artifact_type: hearing_delta_log` 的“庭审偏差与待办记录”。它只记录相对庭前底稿的变化及庭后动作，不另建通用的突发事件、争点变化和立场变化三套台账。
- `position_tension` 只表示当庭表述与既有书面立场可能存在张力，必须标记 `lawyer_review_required=true`；未经完整语境、授权范围和法律效果核验，不得自动认定为自认、放弃、变更请求或越权代理。
- `record_source` 记录当前信息载体，可为 `lawyer_notes`、`court_record`、`court_audio_video` 或 `other`；`court_record_status` 独立记录正式笔录处于 `not_obtained`、`obtained_pending_review`、`verified` 或 `unavailable`。二者不得压成单一状态，`lawyer_notes + not_obtained` 是合法组合。
- 律师笔记回写 A1 事实表时使用 `source_role: lawyer_observation`，另以 `statement_actor` 标明法院、哪一方、证人或其他发言者，并保持 `fact_status: pending`，直至被原件或正式记录核验。不得因记录人是律师就把内容自动归为 `party_assertion`、`analysis_inference` 或法院确认。
- 只有正式笔录核对完成后才使用 `court_record_status: verified` 并记录核验日期、方式及更正项；`court_recorded_undisputed` 仅用于笔录确实记载且无争议的内容，`court_finding` 仅来自裁判认定。法院允许并能够取得时再复核，不要求当庭拍照、复制或立即取得完整笔录。
- 庭审偏差表中的庭后动作转入 `artifact_type: post_hearing_action_list`；含期限的事项同步更新 A0 期限总表。新情况先回写共用底座，再按 `correction_cascade` 更新依赖文书并标记过期版本，不重复建立同一待办。

### 撤回与和解分支

- 二审判决宣告前申请撤回上诉，须由二审法院依法裁定；不能把当事人表示撤回直接写成程序已经终结。
- 一审裁判明显错误或当事人恶意串通损害他人利益等情形，撤回上诉可能不被准许，需按现行司法解释专项核验。
- 二审调解书送达、撤回一审起诉、撤回上诉和当事人自行和解的程序效果不同，分别核验并记录，不用“双方和解”概括全部后果。

## A6 二审终局处理、交付与归档

进入本阶段前再次核对 A5/A6 门禁。`terminal_event` 必须结构化记录 `carrier_type`、`source_locator`、`event_time`、`verification_status` 和 `content_scope`；缺少可读取终局文书和已核验官方事件时停止，并保持 A5 `waiting_external`。

1. 只有已核验官方事件但尚无全文时，使用 `artifact_type: terminal_status_receipt`、`output_scope: procedure_status_only` 和 `run_status: waiting_external`，仅记录当前程序状态、官方载体、送达或取得情况、期限与待办；禁止推断实体结果、裁判理由和权利义务影响。
2. 取得完整终局文书后，使用 `output_scope: full_terminal_analysis`。判决或裁定逐项对比原审与二审主文、认定、理由、费用和后续影响；调解书核对约定义务、生效、履行保障、违约后果和费用；准许撤回上诉裁定核对程序终结、原审裁判状态及费用，不虚构实体再审理结论。`other_terminal_document` 只按可核实程序效果处理并交律师复核，`unknown` 在取得全文并识别类型前不得进入完整分析。
3. 核对文书送达、生效或终审状态、履行期限、保全衔接和费用负担；任何期限进入 A0 期限总表。
4. 以判决上诉一般自二审立案之日起三个月、裁定上诉一般三十日作为现行法检索锚点；记录实际立案日、延长依据和当前状态，不得把法定审限等同于必然结案日期。
5. 发回重审时核对上诉费退还、原审诉讼费处理和新一审交接；再审、执行或其他后续程序只作边界提示并转专项流程。
6. 形成与实际 `output_scope` 相符的客户版和团队归档版，核验文件可读、目录完整和敏感信息处理。

## 场景裁剪与外部等待

| 场景 | 处理 |
|---|---|
| 本方仅准备上诉 | A0–A4 后等待法院送达、排期或补正通知 |
| 本方仅作为被上诉人 | A0 核对对方上诉与我方答辩期，A1–A5 围绕对方轨道处理 |
| 双方均上诉 | 每份上诉独立轨道，共用底座并做交叉一致性检查 |
| 小额诉讼或其他一审终审 | A0 阻断普通上诉文书，列明专项核验与其他可能救济边界 |
| 三类裁定上诉 | 使用受控裁定子路径，重点处理可上诉性、十日期限和费用规则 |
| 其他裁定 | 不生成普通裁定上诉状，进入专项核验闸门 |
| 对方上诉状尚未送达 | 不假想其理由，状态为 `waiting_external`；仅整理原审底座与风险预案 |
| 二审已经开庭 | 从 A5 切入前快速补做 A0、A1 和现有上诉轨道一致性核对 |
| 已核验终局通知但尚无文书全文 | A6 仅生成程序状态回执并等待全文，不分析实体结果 |
| 调解书或准许撤回上诉裁定 | A6 按对应终局文书分支处理，不套用判决主文比较 |
| 无中国境内住所或专项领域 | 标记 `specialist_review_required=true`，仅在专项核验后确认期限和程序结论 |

阶段组完成时运行 `references/appeal-quality-checklist.md` 对应 D0–D6。固定结构从 `references/appeal-templates.md` 按需读取，不要一次加载全部模板。
